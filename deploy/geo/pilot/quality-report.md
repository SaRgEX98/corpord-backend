## Реальная подложка — HTTP-проверки PASS

Прогон `quality.py maps` на `http://127.0.0.1:8092` проверил оба фактических
стиля `/styles/corpord-light.json` и `/styles/corpord-dark.json`.
Архив `yekaterinburg.pmtiles`: 6 462 836 байт, PMTiles v3, bbox заголовка точно
равен bbox пилота, zoom 0–14. Источник manifest: разрешённый архив
`https://build.protomaps.com/20261031.pmtiles`, OSM replication timestamp
`2026-10-31T04:00:00Z`; Basemaps 5.7.2. Это не скачивание публичных тайлов OSM.
SHA256 фактического архива:
`f86daa943da333c07ba8b1270adb64bf74b8804030136bb292c0c4e3c67ec31f`.
Счётчики заголовка независимо проверены: 360 addressed tiles, 360 entries,
360 contents; отсутствие пустого архива не подменяет браузерный осмотр тайлов.

Проверены HEAD/Accept-Ranges/размер, Range206/точный Content-Range и заголовок
архива, недопустимый Range416, ETag304, Cache-Control, CORS для localhost:3000
и отсутствие разрешения для чужого origin, атрибуция OpenStreetMap в источниках
обоих стилей. По HTTP доступны sprites JSON/PNG обоих стилей и Cyrillic block
1024–1279 всех реально используемых Noto Sans Regular/Medium/Italic, включая
ветви выражения `text-font`. Полный отчёт: `maps/quality-results.json` вне Git.

Корневой агент отдельно выполнил браузерную проверку реальной подложки: 1/1 PASS.
Осмотрены light/dark/mobile screenshots: дороги, здания и кириллические подписи
видны, маркеры используют primary темы, атрибуция видима, запросы только локальные.
Проверка выявила отсутствующий module worker MapLibre 6 (404); корневой агент
исправил выдачу worker через Vite asset и повторил успешный браузерный прогон.

## Реальный Photon — структурные проверки PASS, релевантность с ограничениями

Реальный сервис `http://127.0.0.1:2333` содержит 49 919 импортированных объектов
из Geofabrik `ural-fed-district-261031.osm.pbf`, timestamp OSM
`2026-10-31T21:23:06Z`. Объём исходника 396 673 710 байт; supplier MD5 проверен
агентом импорта. SHA256 фактического импортного JSONL:
`251d0673be37ee0ca412f72bb5f513e19f8675ed084128914e3a48462f1b454d`.

Генератор выбрал 40 русских запросов с ожидаемыми ID из импортного источника
**до** получения результатов Photon. SHA256 query fixture:
`3bbb1ea72cb4cf68892c862af7649ec6705b9593ab9b7ac5e97c43f4fcffa600`.
Три последовательных повтора: 120/120 HTTP-запросов успешны, структурных ошибок 0,
p50 **67,0 мс**, p95 **181,0 мс** (HTTP/download, один клиент, без параллельной
нагрузки; первый запрос включён, это не cold restart и не production SLA).
Каждый результат имеет валидный GeoJSON Point, координаты в bbox, OSM ID из
источника, совпадающие centroid/osm_key/osm_value; повторов одного ID в ответе нет.

Все 19 полных имён/адресов находят исходный ID в пределах top10 (57/57 повторов).
Всего ID найден в 93/108 попыток с определённым ожидаемым объектом. Отрицательные
результаты сохранены: префикс «Екатерин» не возвращает city N27503892 в top10
(там POI со схожим названием); короткое «Урал» находит другие одноимённые объекты;
«Гимназия» не обязана отдавать конкретную гимназию №174; опечатка «Восточная
втостанция» даёт пустую выдачу. При одинаковом названии «Сибирский тракт»
возвращается другой настоящий segment W20551508 вместо ожидаемого W1004430226.
Эти случаи не скрыты и не подменены более удобными фикстурами.

Вывод ревью: адреса и полные имена на данном небольшом наборе пригодны для
дальнейшей интеграции; устойчивость к опечаткам и ранжирование префиксов ограничены.
Города/остановки Corpord нужно продолжать искать в собственной БД, как требует
план; raw Photon не заменяет внутренний справочник и явное сопоставление остановки.
Для выбора между одноимёнными OSM-объектами нужны ID/тип/адрес/география, не строка.

Raw Photon на некорректный bbox возвращает 400, на `limit=-1` — 200 (upstream
нормализация, не автоматически дефект Corpord). Валидация публичного Go API
проверяется отдельно. Проверены safeguards harness: loopback/scheme/redirect,
bbox/NaN, расчёт percentile и отказ принимать tiny synthetic fixture за пилот.
Raw queries/results: `photon/quality-queries.json`, `photon/quality-results.json`
вне Git; текущий отчёт содержит агрегаты и рассмотренные ограничения.

Ограничения источника: только selected nodes/ways, без relations/interpolation;
38 548 объектов не имеют явного addr:city; 34 589 way-координат — bbox centers,
которые не являются входами/точками посадки и могут не лежать внутри полигона.
Покрытие ограничено bbox, источник времени отличается от timestamp карты.

Совпадение выдачи Photon с импортированными OSM ID/центроидами подтверждает
import parity, а не независимую географическую истину. Два производных OSM
набора не заменяют подтверждение адреса/места посадки перевозчиком.
