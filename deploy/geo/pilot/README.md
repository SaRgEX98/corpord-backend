# Реальный городской геопилот Corpord

Проверено 2026-11-01 на отдельном локальном стенде, без изменения действующего
приложения. Покрытие — Екатеринбург, bbox `[60.45,56.72,60.75,56.92]`.
Это проверка выбранного бесплатного/open-source стека, не готовность всей России.
Данные OSM бесплатны по лицензии; собственный сервер, хранение и обновление
требуют ресурсов. Публичные Nominatim, demo Photon и тайлы OSM не используются.

## Воспроизведение

1. [Photon](photon.md): скачать закреплённый Geofabrik PBF, проверить checksum,
   подготовить JSONL и импортировать в отдельный индекс Photon 1.3.0.
2. [Карта](map-README.md): выделить разрешённый фрагмент Protomaps PMTiles,
   подготовить собственные стили обеих тем, glyphs/sprites и запустить nginx.
3. [Качество](quality-README.md): сформировать ожидаемые OSM ID из исходного файла,
   выполнить 40 запросов по три раза и проверить Range/CORS/кириллицу карты.
4. Необязательно: [точная граница](city-boundary.md) создаёт **новую копию** данных
   с происхождением дополненного city; baseline не изменяется. Новый индекс
   импортируется и проверяется отдельно, по тем же запросам.
5. Из frontend integration checkout запустить изолированный E2E ниже.

Все PBF/JSONL/PMTiles/индексы, исходные ответы, метрики и screenshots хранятся вне
Git в `corpord-geo-pilot-data`. Зависимости подготовки закреплены в скриптах;
Python/Shapely/osmium не являются зависимостями рабочего Go API.

## Измеренные результаты

| Проверка | Результат |
| --- | --- |
| Источник адресов | Geofabrik Урал, OSM 2026-10-31T21:23:06Z, PBF 396 673 710 B |
| Индекс | 49 919 кандидатов → 49 872 документа; 47 без имени/номера не индексируются |
| PBF → JSONL | 298.53 s, max RSS ~1.02 GiB, наблюдённый временный диск ~1.3 GiB |
| Baseline import | 66.84 s, наблюдённый cgroup memory.peak ~754 MiB, без OOM |
| Baseline restart | 14.41 s до подтверждённого реального city/address ID |
| Карта | 6 462 836 B, 360 MVT tiles, zoom 0–14; extract 27.83 s |
| Raw Photon baseline | 120/120 успешных HTTP, 0 структурных ошибок; p50 67 ms / p95 181 ms |
| Релевантность baseline | Полные имена/адреса 19/19; префиксы 5/8, опечатки 5/6, неоднозначные 2/3 |

Задержки — один последовательный клиент, не нагрузочный SLA. Совпадение ID с
импортом проверяет сохранность источника, а не независимую точность мест посадки.
Карта и адреса используют разные датированные снимки OSM; расхождения возможны.

У baseline только 11 371 кандидатов (22.8%) имеют явный город. Отдельная копия
`city-enrichment-v1` добавила city 13 957 **точкам** внутри точной relation 6564910,
с отступом 100 м от всех внешних/внутренних границ. Существующие города сохранены;
приблизительные центры ways исключены. Теперь city имеется у 25 328 кандидатов
(50.7%), остальные остаются неизвестными. Геометрия: 83 ways, 6816 nodes,
1 polygon / 23 holes; SHA256 зафиксирован в скрипте и provenance. Импорт копии
завершился за 59.16 s, ExitCode 0, OOMKilled false; отдельный пик RAM не измерялся.
Повтор тех же 40 запросов × 3 сохранил все ожидаемые совпадения: 120/120 HTTP,
0 структурных ошибок; p50/p95 93.9/293.9 ms. Свежий baseline control дал
98.6/214.8 ms; это разные последовательные прогоны, без причинного вывода о
производительности enrichment. Результаты сравнительного поиска приведены в [отчёте](quality-report.md).

## Реальное приложение в браузере

Frontend требует Node согласно package.json (локально проверен Node 26.1).
Нужны заранее собранный согласованный backend image, запущенный локальный Photon
с label `corpord.geo.pilot=true`, собственные стили и Chromium Playwright.

```bash
CORPORD_E2E_BACKEND_IMAGE=corpord-backend:geo-integration-test \
CORPORD_E2E_PHOTON_CONTAINER=corpord-geo-pilot-city \
CORPORD_E2E_WEB_PORT=3200 \
CORPORD_E2E_MAP_STYLE_URL=http://127.0.0.1:8092/styles/corpord-light.json \
CORPORD_E2E_MAP_DARK_STYLE_URL=http://127.0.0.1:8092/styles/corpord-dark.json \
CORPORD_E2E_GEO_PILOT=1 CORPORD_E2E_REAL_MAP_TEST=1 npm run test:e2e:isolated
```

Harness создаёт собственные PostgreSQL/Redis/backend, тестовые аккаунты и временную
сеть, подключает к ней только явно помеченный Photon и отключает при очистке.
Не читает реальные `.env`, не меняет приложение и не удаляет переданный Photon.
URL стилей должны быть loopback. Общий тест проверяет реальную подсказку через Go
адаптер → явный город → собственную тестовую остановку. Карта проверяет настоящие
PMTiles/glyphs, светлую/тёмную/mobile темы, отсутствие публичных запросов; маршрутные
API в этом отдельном тесте карты подменены fixtures. Самостоятельный тест адреса
подмен API не использует. Снимки лежат в frontend `test-results/real-map-*.png`.

Пилот выявил и исправил отсутствующий production worker MapLibre 6 (`?url` и
`setWorkerUrl`) и PostgreSQL `integer = text` при выборе остановок города.
Ошибку SQL дополнительно воспроизводит Go integration regression с реальной БД.

## Завершение и дальнейшее включение

Остановить только свои pilot-контейнеры через `photon_runtime.sh stop`, удалить
завершившиеся `*-import` и выполнить `docker compose -f map-compose.yaml down`
с правильным `MAP_DATA_DIR`. Сохранить датированные данные вне Git для повторного
запуска; имена/порты второго Photon задаются `PHOTON_PILOT_NAME/PHOTON_PILOT_PORT`.
Не использовать глобальную очистку Docker.

Перед включением на целевом окружении нужны согласованные регионы, домены/CORS,
резервирование и обновление данных, нагрузочный бюджет и подтверждённое соответствие
остановок перевозчика. Неизвестный city остаётся неизвестным. Внешнее место никогда
не становится остановкой автоматически. Собственный поиск городов ранжируется по
совпадению названия, связанности, наличию рейсов и редакционному приоритету; машинное обучение не требуется.
Места, резервы и надбавки спроса требуют отдельного достоверного источника и правил.
