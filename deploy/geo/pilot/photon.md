# Реальный ограниченный пилот Photon

Дата: 2026-11-01. Это отдельный исследовательский стенд; он не меняет действующие
приложения, БД, системные sysctl и production-конфигурацию. Все исходные данные,
индексы, результаты и журналы находятся **вне Git**.

## Источник и границы

Пилот использует [датированную выгрузку Geofabrik Уральского ФО](https://download.geofabrik.de/russia/ural-fed-district-261031.osm.pbf)
(396 673 710 байт). Проверяются контрольная сумма MD5 поставщика и закреплённый SHA256
`4b75d5d4d4850bb80999d32844032626545a2068da8b4538cadb154818dc3ec0`.
Данные © OpenStreetMap contributors, [ODbL](https://www.openstreetmap.org/copyright).
Geofabrik не включает user names/IDs/changeset IDs в публичный PBF.

Выделяются только точки и линии с центром в bbox `[60.45,56.72,60.75,56.92]`
(долгота/широта, Екатеринбург). Это неполное покрытие города, тем более не РФ.
Классы: place, именованные amenity/railway/public_transport/tourism/shop/leisure/highway,
а также объекты с явными `addr:street` + `addr:housenumber`.
`source-objects.jsonl` сохраняет реальные OSM type/ID, исходные теги и способ координат.
Данные не являются ручной фикстурой и не используют вымышленные OSM ID.

Выход `photon.jsonl` соответствует официальному [формату interchange Photon 0.1.0](https://github.com/komoot/photon/blob/1.3.0/docs/json-dump-format-0.1.0.md).
Поле generator честно указывает `corpord_osm_pbf_pilot`, а не Nominatim.
Это допустимый отдельный генератор формата, **не импорт Nominatim**.

Ограничения относительно полноценного Nominatim:

- Адресная иерархия берётся только из явных `addr:*`; отсутствующий город/регион
  остаётся пустым. Близость к центру города не используется для присвоения города.
- Координаты ways — центр bbox по их узлам; это не вход и не гарантированная точка
  внутри здания. Для nodes сохраняются исходные координаты.
- Relations, associatedStreet, интерполяция номеров и административная вложенность
  не разрешаются. Нет Nominatim importance/Wikipedia ranking.
- Отбор по центру bbox может исключить пересекающий границу объект.
- `country_code=ru` — явно объявленный региональный scope пилота, не вычисленная
  геометрия государства. Названия города/страны/региона не дописываются вручную.
- Для связи внешнего POI с городом Corpord нужен фактически возвращённый город.
  Пустой `city` не означает Екатеринбург; UI не должен предлагать остановки догадкой.

## Воспроизведение

Требования: Python с venv, Docker, уже собранный закреплённый `corpord-photon:1.3.0`
из `../Dockerfile.photon`, достаточное место. Подготовку и контейнеры запускать
последовательно, не одновременно с тяжёлой сборкой карты. Цель: данные до 5GB,
один контейнер до 3GB, общий RAM пилота до 5GB. Бюджет загрузки OSM до 500MB.
Новый регион/источник требует нового sizing; загрузка planet не предусмотрена.

```bash
python3 -m venv /tmp/corpord-geo-osmium
/tmp/corpord-geo-osmium/bin/pip install 'osmium==4.1.1'
# Абсолютный путь вне репозитория, для каждого обновления новый каталог.
pilot_dir=/absolute/path/corpord-geo-pilot-data/photon
python3 deploy/geo/pilot/photon_download.py "$pilot_dir"
/tmp/corpord-geo-osmium/bin/python deploy/geo/pilot/photon_prepare.py \
  "$pilot_dir/ural-fed-district-261031.osm.pbf" "$pilot_dir"
bash deploy/geo/pilot/photon_runtime.sh import "$pilot_dir"
bash deploy/geo/pilot/photon_runtime.sh serve "$pilot_dir"
curl --fail --get --data-urlencode 'q=Екатеринбург' \
  --data 'lang=ru&limit=5' http://127.0.0.1:2333/api/
```

Загрузчик сохраняет частично загруженный PBF и продолжает только при корректном
HTTP Range; автоматических повторов нет. Одна попытка ограничена 900 сек
плюс текущий socket read с таймаутом 60 сек. Оператор повторяет после сетевой ошибки,
сохраняя уже полученные байты. Имя/размер источника закреплены; изменившийся файл
не импортируется молча. MD5 поставщика проверяется до конвертации. SHA256 сохраняется
в manifest вместе с URL, временем OSM из PBF header, bbox, количеством типов,
отсутствующей иерархией, длительностью подготовки и хешами производных файлов.
Конвертер отказывается затирать существующие результаты; при обрыве использовать
новую версию каталога. Индекс координат `locations.idx` временный и после успешной
конвертации удаляется.

Импорт работает с отключённой сетью; serve публикует только `127.0.0.1:2333`,
внутри контейнера порт `2322`. Имя `corpord-geo-pilot-photon`, label
`corpord.geo.pilot=true`. Heap 1GB, hard limit 3GB, 2 CPU, 512 PID. Import-контейнер
сохраняется после завершения для проверки ExitCode/OOMKilled и удаляется явно после
сохранения журнала. Изменять sysctl для этого стенда запрещено; при bootstrap-ошибке
запуск прекращается и причина фиксируется.

Для E2E допустимо временно присоединить Photon к **отдельной тестовой Docker-сети**.
Не присоединять его к сети рабочего Corpord и не менять конфигурацию рабочего API.
Публичный Nominatim, Photon demo и публичные тайлы не участвуют в runtime.

## Обновление и откат

Инкрементальных обновлений этого прямого конвертера нет. Повторить подготовку в
новом каталоге, проверить качество/ресурсы, остановить только пилот, запустить новый
индекс с тем же именем/портом. Старый каталог сохраняется до проверки нового.
Откат — остановить пилот и запустить сохранённый индекс; внутренние ID Corpord не
изменяются. Настоящее production-переключение/период обновлений решаются отдельно.

```bash
bash deploy/geo/pilot/photon_runtime.sh stop "$pilot_dir"
# После сохранения результатов и завершения E2E, только известный import-контейнер:
docker rm corpord-geo-pilot-photon-import
```

## Измеренные результаты 2026-11-01

Реальная подготовка завершилась: OSM snapshot **2026-10-31T21:23:06Z**,
49 919 исходных кандидатов, 49 872 индексированных документа. Разница — 47 place
без имени и номера дома (7 islet, 1 allotments, 7 square, 32 quarter), которые
Photon не индексирует как поисковые документы; это проверено сравнением source
и внутреннего OpenSearch `_cat/indices`, доступного только внутри контейнера.
Источник не потерян из-за отсутствия необязательного CountryInfo.

Из 49 919 кандидатов только **11 371 (22.8%)** имеют явный `addr:city`.
У 38 548 город отсутствует; 34 589 координат вычислены как way bbox center.
Сырой `source-objects.jsonl`, `manifest.json`, логи, ресурсные замеры, индексы и
ответы находятся в локальном `corpord-geo-pilot-data/photon`, вне Git.
Скрипт замера cgroup при импорте сохраняет наблюдённый kernel memory.peak;
очень краткий пик после последнего чтения перед удалением cgroup теоретически
мог не попасть в отчёт. Heap 1 GiB и hard limit 3 GiB оставались включены.

Проверенные реальные примеры:

- `Екатеринбург` возвращает город N27503892, но на второй позиции после POI с
  таким же именем: без Nominatim importance общий ranking ещё требует улучшения.
- `улица Соболева 3` возвращает N423738494 «Нягань-Газ» с явным
  `city=Екатеринбург`, адресом и номером дома. Первый building W114507457
  имеет тот же адрес, но без city. Нельзя брать первый результат без выбора.
- `Северный автовокзал` возвращает реальный N1611971920 и варианты остановок;
  city отсутствует. Автоматическая связь с остановками Corpord здесь запрещена.
- `Путёвка` возвращает фактическую железнодорожную станцию N193723282 и
  отдельные одноимённые остановки; это разные OSM сущности.

Пилот подтверждает возможность реального регионального self-host индекса в этих
ресурсах, но не полное качество адресной иерархии. Production-включение внешних
подсказок остаётся закрытым до решения отсутствующего city/регионов и последующей
проверки. Полный протокол русских запросов/ошибок и их задержки хранится отдельно
в `quality-report.md`; результаты его нельзя заменять этими примерами.

Официальные источники: [Photon import/serve](https://github.com/komoot/photon/blob/1.3.0/docs/usage.md),
[Pyosmium](https://docs.osmcode.org/pyosmium/latest/reference/Handler-Processing/),
[Geofabrik регион](https://download.geofabrik.de/russia/ural-fed-district.html).
Первоначальные одиночные проверки Overpass завершились 502/timeout; публичный API
не используется как зависимость или фоновый сервис приложения. Массовые запросы
и обход ограничений не выполнялись.
