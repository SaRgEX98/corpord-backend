# Точная граница Екатеринбурга: отдельный эксперимент

Проверено 2026-11-01. Исходный Photon dump, baseline index и сервисы не изменены.
Экстракт использует уже скачанный Geofabrik PBF `ural-fed-district-261031.osm.pbf`.
Новых геоданных не скачивает. Геометрия/результаты сохраняются вне Git.

Идентичность фиксирована: OSM relation **6564910**, `place=city`,
`type=multipolygon`, `wikidata=Q887`, `name=Екатеринбург`.
Это не муниципальный округ relation 1104258 (`admin_level=6`, Q4307474).
Подмена муниципальным округом или прямоугольником запрещена кодом.

## Запуск

```bash
python3 -m venv /tmp/corpord-geo-osmium
/tmp/corpord-geo-osmium/bin/pip install -r deploy/geo/pilot/city-boundary-requirements.txt
/tmp/corpord-geo-osmium/bin/python deploy/geo/pilot/city-boundary.py \
  /absolute/data/photon/ural-fed-district-261031.osm.pbf \
  /absolute/data/photon/city-boundary-v1
/tmp/corpord-geo-osmium/bin/python -m unittest discover -s deploy/geo/pilot -p test_city_boundary.py -v
```

Выходная директория должна отсутствовать. SHA256 исходного PBF и GeoJSON
закреплены по проверенному снимку; несовпадение останавливает работу до создания
выходных файлов. Перед enrichment checksum геометрии проверяется повторно;
он также сохраняется в provenance каждого дополненного объекта.
Код читает три прохода: одна relation,
только её ways, только узлы этих ways. Entity/ID-фильтрация выполняется C++
`osmium.filter.IdFilter`, Python не получает все узлы региона и не создаёт
общерегиональный location cache. Проверяется полнота каждого way/node, роли
outer/inner, замкнутость колец, отсутствие cuts/dangles/invalid segments,
однозначное вложение holes и валидность итогового MultiPolygon. Автоматического
исправления геометрии (`buffer(0)`, `make_valid`) нет; любая неоднозначность — ошибка.

`city-boundary.geojson` содержит исходные tags, IDs всех members, PBF SHA256,
источник, OSM timestamp и ODbL attribution; `boundary-stats.json` — контрольную
сумму геометрии, состав, ресурсы. Shapely/numpy используются только подготовкой,
не становятся runtime-зависимостями backend. Их лицензии поставляются в пакетах.

## Необязательное создание новой копии dump

Только после оценки геометрии можно добавить аргумент `--enrich-copy` с исходным
`photon.jsonl`, **используя новую выходную директорию**. Исходный файл не меняется;
результат никуда не импортируется и сервисы не переключаются.

```bash
/tmp/corpord-geo-osmium/bin/python deploy/geo/pilot/city-boundary.py \
  /absolute/data/photon/ural-fed-district-261031.osm.pbf \
  /absolute/data/photon/city-enrichment-v1 \
  --enrich-copy /absolute/data/photon/photon.jsonl
```

Заполняется только отсутствующий `address.city`, именем из tags relation, если
исходная точка **строго внутри** точного полигона и дальше **100м** от любой его
внешней/внутренней границы. Защитная метрика намеренно консервативная: расстояние
в градусах умножается на минимальный масштаб метров/градус в широтной полосе
города (минимальный радиус кривизны Земли и дополнительный запас 1%). Она
недооценивает расстояние, особенно с севера на юг, поэтому отбрасывает лишние
точки около границ. Это локальный метод для данной геометрии, не универсальный
геодезический API и не основание переносить алгоритм на другие регионы.

Явные `addr:city` всегда сохраняются; несовпадения считаются отдельно как conflicts.
Точки на границе, в holes, с неизвестным/невалидным методом координат исключаются.
**Все ways с `way_bbox_center` пропускаются**, даже глубоко внутри: исходный dump
не содержит extent объекта, и по одному центру невозможно доказать, что длинная
дорога или здание не пересекает границу. Узлы тоже не доказывают положение входа
в здание; обогащение относится только к исходной точке OSM.

Каждая новая city получает `extra.city_provenance`: relation ID, source SHA256,
метод координат/сопоставления и отступ. Итоговые counts и SHA256 исходной/новой
копий сохраняются в stats. Качество enriched dump и его индекс нужно измерять
отдельно от baseline; этот эксперимент сам по себе не разрешает включение в продукт.
