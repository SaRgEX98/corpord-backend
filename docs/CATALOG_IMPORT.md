# Общероссийский справочник и демонстрационное расписание

Версия реализации: 2026-11-03. Данные, индексы, Python venv и отчёты измерений
хранятся **вне Git**. Изменения не запускают импорт при старте API и не включают
Photon/карты на всю страну.

## Источники и границы покрытия

- Закреплённая выгрузка OSM: https://download.geofabrik.de/russia-261102.osm.pbf
  (4 194 615 984 B); опубликованный MD5 `725964e01f0e1a65acd92ef4e893c48d`.
  https://download.geofabrik.de/russia-261102.osm.pbf.md5 .
- `prepare.py` записывает SHA-256 исходника/JSONL, источник и версию набора в manifest.
  OSM: ODbL-1.0, © участники OpenStreetMap. Границы и названия соответствуют
  выбранному источнику. Выгрузка Geofabrik может включать приграничные объекты.
- Импортируются именованные `place=city/town`, автобусные станции и остановки,
  автобусные платформы с явным `bus=yes`. Это покрытие OSM, а не подтверждённый
  официальный реестр всех юридических городов РФ. Сёла/деревни и все адреса в
  этот профиль не входят. Несовпадение с официальным реестром требует сверки.
- Регион — точный OSM admin_level=4 polygon, включая holes. Профиль соответствует
  охвату Russia Geofabrik: OSM-коды `RU-*` и `UA-43/UA-40` для Крыма/Севастополя,
  которые Geofabrik включает в эту выгрузку. Исходные коды не переписываются;
  выбор географического покрытия не является изменением ISO-классификации.
  При отсутствующей/неоднозначной геометрии город остаётся в `review.jsonl`.
  Региональные PBF могут обрезать целые границы, поэтому контроль проводится
  на национальном исходнике. Вспомогательные `subarea` не означают геометрию.
- Остановка связывается с городом по полигону **населённого пункта**, либо по
  явному `addr:city/is_in:city`, однозначному имени в точном регионе и защитному
  ограничению расстояния. Ближайший город сам по себе не является основанием.
  Неизвестная привязка сохраняется NULL и отдельно попадает в review.
- Станция, платформы и противоположные стороны дороги могут быть разными
  объектами OSM. Они сохраняют разные source_key; совпадение имени/близость
  не склеивают разные места посадки. Автоматическая группировка по stop_area
  пока отсутствует. Для демонаправления выбирается одна остановка города,
  с приоритетом bus_station. Открытые/неполные ways без проверенного area
  не превращаются в произвольные точки — счётчик пропусков есть в manifest.
- Полный набор `timezonefinder==8.3.0`, `timezonefinder-data==1.2026.3` даёт
  географические IANA ID. Сокращённые same-since-now наборы запрещены:
  одинаковый UTC offset не означает одинаковый часовой пояс. Контрольные
  города (Москва, Екатеринбург, Владивосток, Петропавловск-Камчатский) проверяются
  тестом. При неустановленном поясе сохраняется unknown, расписание не генерируется.
  У timezone-boundary-builder свой источник и лицензия ODbL; код timezonefinder
  MIT. Версии сохраняются в manifest.

## Подготовка и запуск

Использовать отдельную тестовую БД и аккаунты. Переменная `CATALOG_DATABASE_URL`
передаётся из локального окружения; не помещать URL/пароли в Git или отчёт.
Сначала применить обычные Goose-миграции backend (включая `20261103000100`).
Для `pg_trgm` нужны права установки extension либо его предварительная установка
DBA в `public`. Миграция не удаляет общую extension при rollback.

```bash
python3 -m venv /path/outside-git/catalog-venv
/path/outside-git/catalog-venv/bin/pip install -r scripts/catalog/requirements.lock.txt
# Скачать закреплённый исходник и сверить опубликованный checksum.
/path/outside-git/catalog-venv/bin/python scripts/catalog/prepare.py \
  --pbf /data/russia-261102.osm.pbf --output /data/russia-catalog-v1 \
  --source-url https://download.geofabrik.de/russia-261102.osm.pbf
# По умолчанию импорт проверяется в транзакции с ROLLBACK.
/path/outside-git/catalog-venv/bin/python scripts/catalog/import_catalog.py \
  --directory /data/russia-catalog-v1
# --apply фиксирует проверенный импорт.
/path/outside-git/catalog-venv/bin/python scripts/catalog/import_catalog.py \
  --directory /data/russia-catalog-v1 --apply
/path/outside-git/catalog-venv/bin/python scripts/catalog/demo.py \
  --dataset russia-demo-v1 --days 30 --directions 10000 --departures 2 --apply
```

Оба изменения транзакционны, используют один advisory lock и COPY в staging;
API при этом продолжает читать предыдущий committed набор. Данные проверяются
до публикации. Служебный lock_timeout 5s не позволяет зависать на чужих DDL.
Идентификаторы source_key стабильны, совпадающие имена разных городов в одном
регионе допустимы. Нельзя использовать `(name,region)` как идентичность города.

Повторение диапазона не создаёт записи, пересечение добавляет только новые даты.
Конфигурация demo dataset неизменяема; для других параметров нужен новый ID.
Перезапуски в разные даты расширяют историю: автоматического TTL/удаления нет.
Не запускать seed ежедневно без отдельной политики retention.

Импорт обновляет только неизменённые собственные записи (сравнение снимка).
Ручные изменения защищены. Другой timezone или mapping существующей остановки
не меняется автоматически: такие расхождения считаются конфликтами в результате
и требуют отдельного решения, особенно если уже есть расписание. Исчезнувшие из
источника записи не удаляются. Изменение имени не меняет source_key. Удалённая
отслеживаемая запись останавливает импорт. Уникальный legacy город с совпадающим
именем/регионом/поясом может быть связан без присвоения владения; только отсутствующие
координаты дополняются источником, прочие ручные поля сохраняются.

Деморасписание — синтетическое: близкие города до 300 км, максимум 10 000
**направленных** связей, обратные рейсы и до двух подходящих промежуточных городов.
Не проверяется реальный дорожный граф, паромы/границы, действующие перевозчики
или нормативы рабочего времени. Точки/автостанции реальные, расписание/цены/
автобусы/водители явно тестовые. Рейсы получают `is_demo=true` в API и интерфейсе.
Каждой паре/слоту выделяется свой автобус и два водителя; возврат и запас времени
должны закончиться до следующего дня. Перед добавлением проверяются пересечения
с уже существующим использованием этих автобусов/водителей. Повтор после удаления
отслеживаемого рейса прекращается. Аккаунты, заказы и платежи не создаются;
наличие мест всегда unknown. Денежные суммы генерируются в целых копейках.

## Поиск, N+1 и lazy loading

- `catalog_search`: синхронные триггеры insert/update/delete. Ручной CRUD сразу
  виден в поиске, фоновый refresh materialized view не нужен. Изменение города
  обновляет регион/пояс его остановок; служебные обновления снимков не переиндексируют
  неизменённые названия. Отдельного Elasticsearch для этого справочника нет.
- Нормализация регистра, пробелов и ё/е; B-tree для коротких префиксов и
  принадлежности городу/региону; GiST pg_trgm KNN для опечаток, GIN для текста.
  `%`, `_`, backslash в пользовательском вводе экранированы, SQL параметризован.
- Подсказки: максимум 64 кандидата на ветку, затем проверка текущих рейсов и
  связности; served проверяется только после shortlist; достижимые остановки исходной точки
  вычисляются одним общим CTE и повторно используются всеми кандидатами. Порядок устойчив
  по имени/ID; shortlist означает приближённое ранжирование, не глобальный рейтинг.
  Для пустого ввода показываются только проверенные обслуживаемые точки;
  при явном региональном выборе можно выбрать и город без расписания.
- `GET /catalog/:kind`: `{items,next_cursor}`, default 30, max 100, без OFFSET и
  COUNT(*) на каждый запрос. Cursor связан с kind/q/region/city_id/status/category. ID-порядок
  устойчив; обновления между страницами не являются snapshot транзакцией.
  Пользователи доступны только `/admin/catalog/users` с обычным admin ACL.
- Поиск рейса: 3 SQL-запроса независимо от размера страницы; каталог: 1.
  JOIN возвращает нужные подписи, полный список остановок — только в карточке.
  Индекс `(stop_id,departure_time,trip_id) INCLUDE(stop_order)` ограничивает
  расширение маршрутов датой и местом отправления.
- Соединения API используют `jit=off`: LLVM-компиляция интерактивных запросов
  на большом наборе добавляла секунды к индексным probes. Для аналитики нужен
  отдельный connection profile. LATERAL/OFFSET 0 фиксирует отбор по остановке/
  дате перед расширением маршрутов; обычного наличия индекса оказалось мало
  из-за корреляции «много геоостановок, мало обслуживаемых». `cmd/catalog-plan`
  сохраняет фактические EXPLAIN с отключённым JIT в read-only тестовой сессии.
  Проверка города также использует упорядоченный индекс `(city_id,id)` до
  проверки рейсов: иначе EXISTS выбирал повторный Seq Scan всех остановок.
- Таймаут: подсказки 2s, каталог 3s, поиск/календарь/quote 5s. Отмена клиента
  проходит в PostgreSQL. Timeout возвращает безопасный 503/search_timeout.
- Старые array endpoints, включая `/trips/all`, ограничены **100 записями**.
  Это осознанное изменение совместимости: внешние клиенты должны перейти на
  `/catalog/:kind`. Заголовки `X-Collection-Limit` и `Link` указывают лимит и замену.
  `/locations/:id/stops` — legacy первые 50; полный выбор через `/catalog/stops`.
- Frontend загружает по 20–30 записей, debounce 250ms, отменяет предыдущий fetch,
  защищает состояние generation counter, очищает cursor при смене поиска.
  В DOM хранятся последние 200 карточек/строк (100 вариантов селектора): «ещё»
  последовательно продвигает окно, а не накапливает весь справочник.
- Связанные справочники не загружаются при открытии админкаталога. В редакторе
  загружаются только текущие выбранные записи; остальные ищутся при фокусе.
  Overview читает один SQL со статистикой reltuples и честным знаком ≈.
- Публичные подсказки имеют локальный ограниченный LRU/TTL cache 30s;
  авторизованные ответы в этот cache не попадают. Расписание/quote не кэшируются.
  Детали используют lazy async data, карта сохраняет загрузку по кнопке.

## Проверки и измерения

```bash
TEST_DATABASE_URL=... TEST_REDIS_ADDR=... GOMAXPROCS=2 go test -p 2 -race -count=1 ./...
GOMAXPROCS=2 go vet -p 2 ./...
/path/outside-git/catalog-venv/bin/python -m unittest discover \
  -s scripts/catalog -p 'test_*.py' -v
/path/outside-git/catalog-venv/bin/python scripts/catalog/benchmark.py \
  --api http://127.0.0.1:8083/api/v1 --output /data/russia-benchmark.json
```

Go query tracer проверяет постоянное число SQL для страниц 1/30/100 и поиска
1/20; интеграции проверяют cursor scope, русские названия/ё, literal wildcard,
обновление/удаление индекса. Python проверяет holes, timezone, dry-run/rollback,
повторение/пересечение дат, защиту ручных правок, суммы и отсутствие конфликтов.
Браузерные проверки включают ограниченные страницы, устаревшие ответы, регион,
девять CRUD, calendar/search/quote с реальным PostgreSQL и отдельными аккаунтами.

`benchmark.py` сохраняет размеры таблиц с индексами, общий размер БД, p50/p95,
HTTP ошибки и EXPLAIN (ANALYZE, BUFFERS). Локальные прогоны на прогретом cache
не являются SLA. Планирование ресурсов основывается на национальном прогоне,
а не на размере PBF или предположении о числе остановок.
